<decisions>
## Implementation Decisions

### D-01: Signals are GLOBAL events, not playground-scoped
- **WriteSignal does NOT take a playground_id** — signals are global events
- A signal can be produced without any playground consuming it
- Playgrounds subscribe to signals and store a COPY of consumed ones
- This is a key architectural distinction from orders (which are playground-scoped)

### D-02: WriteSignal RPC — single signal, global scope
- `WriteSignal(name, symbol, timestamp, attributes)` → returns `signal_id` (UUID generated by Go server)
- No playground_id in the request
- Go server validates signal name, generates UUID, stores via ISignalRepository
- Server needs a `globalSignalRepo ISignalRepository` field to store signals outside of any playground
- Telemetry: OTel counter incremented for each produced signal (by name, symbol)
- Note: `SignalsGenerated` counter already exists in `telemetry/metrics.go` — reuse it

### D-03: GetProcessedSignals RPC — per-playground consumed signals
- `GetProcessedSignals(playground_id, filters?)` → returns signals consumed by that playground
- Filters: name, symbol, time range
- Returns copies of signals that were delivered via TickDelta to this playground
- This satisfies RPC-01

### D-04: GetSignals RPC — global signal query
- `GetSignals(filters?)` → returns all signals matching filters from the global store
- Filters: name, symbol, time range
- For live mode: reads from ESDBSignalRepository (global trade-signals stream)
- For sim mode: reads from the global InMemorySignalRepository

### D-05: Python client wrappers
- Add `write_signal()` and `get_processed_signals()` methods to `BacktesterPlaygroundClient`
- These call the auto-generated Twirp client methods
- `write_signal(name, symbol, timestamp, attributes)` → signal_id
- `get_processed_signals(playground_id, name=None, symbol=None, start=None, end=None)` → list of signals

### D-06: Telemetry for signal production
- Reuse existing `SignalsGenerated` counter (increment on WriteSignal)
- `SignalsConsumed` counter already exists (Phase 23) — no changes needed

### Claude's Discretion
- WriteSignal request/response proto message field design
- GetSignals vs GetProcessedSignals proto message field design
- How globalSignalRepo is initialized (inline in NewServer vs constructor param)
- filterSignals helper function design for shared filtering logic
- Exact Python wrapper method signatures beyond the basics in D-05

</decisions>

<specifics>
## Specific Ideas

- Signals are global events — produced independently, consumed optionally by playgrounds
- The globalSignalRepo should be the same type as playground signal repos (ISignalRepository) — for live mode use ESDBSignalRepository, for development/sim use InMemorySignalRepository
- filterSignals helper should be shared between GetSignals and GetProcessedSignals (both filter by name, symbol, time range)
- RecordSignal handler (grpc.go L298) is deprecated — WriteSignal replaces it

</specifics>
