Create `integration_testing/esdb_signal_repository_test.go`:

**Test setup:**
- Use TestContainers to spin up an EventStoreDB container (image: `eventstore/eventstore:24.2.0`). Set environment vars: `EVENTSTORE_INSECURE=true`, `EVENTSTORE_CLUSTER_SIZE=1`, `EVENTSTORE_RUN_PROJECTIONS=All`, `EVENTSTORE_START_STANDARD_PROJECTIONS=false`. Expose port 2113.
- Create an `esdb.Client` connecting to the container.
- Create an `EsdbProducer` using `NewESDBProducer(&sync.WaitGroup{}, connectionString, nil)` -- but since we need the ESDB client directly for reads, and EsdbProducer needs its `Start()` called to initialize `db`, we may need to either:
  a. Call `esdbProducer.Start(ctx, nil)` and then use it, OR
  b. Create the ESDB client directly and use `esdbProducer.Save()` for writes only.

  **Simplest approach:** Create the `esdb.Client` directly for the test. For writes, use `esdbProducer` (needs its db field set). Looking at `EsdbProducer.Start()`, it calls `esdb.NewClient()` internally. For tests, the cleanest pattern is to create a minimal test helper that writes directly via `esdb.Client.AppendToStream()` and reads via the ESDBSignalRepository.

  Actually -- since `ESDBSignalRepository.Write()` calls `esdbProducer.Save()` which needs `esdbProducer.db` to be set (done in `Start()`), the simplest test approach is:
  1. Create esdb.Client directly from TestContainer URL
  2. Create EsdbProducer, call its Start() with a background context
  3. Create ESDBSignalRepository with the esdbProducer
  4. Write signals via the repository, read them back

  If `EsdbProducer.Start()` has too many side effects (subscribes to pub/sub streams, reads from streams), consider an alternative: create a thin wrapper or test the ESDB path more directly. Check what `Start()` does -- it subscribes to pub/sub events and starts reading streams. For a minimal test, you might need to set the `db` field directly. Since `db` is unexported, you may need to add a `SetClient(client *esdb.Client)` test helper on EsdbProducer, OR use the exported `GetClient()` method after calling Start with minimal config.

  **Pragmatic approach:** Use `eventservices.FetchAll` for reads (which takes an esdb.Client) and `esdb.Client.AppendToStream()` for writes directly. This tests the read path of ESDBSignalRepository without needing a full EsdbProducer. Then add a separate sub-test that tests Write() through the full ESDBSignalRepository if the EsdbProducer can be initialized cleanly.
