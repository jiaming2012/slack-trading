<decisions>
## Implementation Decisions

### D-01: Signals are GLOBAL events, not playground-scoped
- **WriteSignal does NOT take a playground_id** — signals are global events
- A signal can be produced without any playground consuming it
- Playgrounds subscribe to signals and store a COPY of consumed ones
- This is a key architectural distinction from orders (which are playground-scoped)

### D-02: WriteSignal RPC — single signal, global scope
- `WriteSignal(name, symbol, timestamp, attributes)` → returns `signal_id` (UUID generated by Go server)
- No playground_id in the request
- Go server validates signal name, generates UUID, stores via ISignalRepository
- Telemetry: OTel counter incremented for each produced signal (by name, symbol)

### D-03: GetProcessedSignals RPC — per-playground consumed signals
- `GetProcessedSignals(playground_id, filters?)` → returns signals consumed by that playground
- Filters: name, symbol, time range
- Returns copies of signals that were delivered via TickDelta to this playground
- This is RPC-01 from requirements

### D-04: Global signal query via ESDB
- Querying ALL produced signals goes through EventStoreDB directly (or a thin RPC layer over it)
- This is distinct from GetProcessedSignals which is per-playground
- For Phase 19: add a `GetSignals(filters?)` RPC that reads from the global signal store

### D-05: Python datasource scripts in datasources/
- Location: `src/clients/python/datasources/`
- Each datasource is a module with a `produce_signals()` function
- Live mode: run from `__main__`, calls WriteSignal RPC
- Sim mode: strategy does `from datasources.ma_crossover import produce_signals` (direct import, no RPC)
- No example datasources built in this phase — infrastructure pattern only (skeleton + __init__.py)

### D-06: Telemetry for signal lifecycle
- **Produced**: OTel counter per signal produced (by name, symbol)
- **Consumed**: OTel counter per signal consumed by a strategy (by playground, name)
- Should show up on Grafana dashboard as signal counts

### D-07: Example datasources deferred to strategy migration
- MA crossover, start-of-week, etc. built during Phase 21-22 when migrating actual strategies
- Phase 19 creates the pattern/skeleton only

### Claude's Discretion

- Exact Python datasource skeleton structure
- How playgrounds store consumed signal copies (separate list vs reference to global store with cursor)
- OTel metric names for signal production/consumption counters
