**Important nuance:** CoveredCall's `check_for_new_signal` depends on `self._get_feature_vector` which needs access to `self.candles_ltf` (a DataFrame of accumulated LTF candles). This makes the datasource function need a callable parameter rather than raw bar data. The feature_vector_fn parameter encapsulates this state dependency. Alternatively, if this coupling is too tight, the datasource can simply wrap the existing check_for_new_signal and check_for_roll_signal methods and the V2 delegates to the datasource wrappers. Use whichever approach keeps the V2's tick() method cleaner while maintaining behavioral equivalence.
