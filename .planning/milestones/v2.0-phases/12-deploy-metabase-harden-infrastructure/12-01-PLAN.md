Create `infra/init-metabase.sql` -- an idempotent SQL script intended to run against the production Postgres (as superuser). Per D-04, this script must:

1. Create database `metabaseappdb` (for Metabase internal state -- questions, dashboards, settings):
   - Use a PL/pgSQL DO block to check if the database exists before creating (CREATE DATABASE cannot use IF NOT EXISTS)
   - Owner: the existing `grodt` superuser (Metabase will connect as grodt to this DB for its app state, simplifying credential management)

2. Create role `metabase_ro` with LOGIN and a placeholder password `CHANGEME_METABASE_RO`:
   - Use `CREATE ROLE IF NOT EXISTS` pattern (DO block with pg_roles check)
   - GRANT CONNECT on database `playground`
   - GRANT USAGE on schema `public` in database `playground`
   - GRANT SELECT on ALL TABLES in schema `public` of database `playground`
   - Set DEFAULT PRIVILEGES so future tables also get SELECT for metabase_ro

Important: The script must handle being run multiple times without errors (idempotent). Use `\c playground` to switch to the playground database before granting schema/table permissions.

Note: The password in the SQL file is a placeholder. The user will change it when running against production.

<task type="auto">
  <name>Task 2: Create local Metabase docker-compose and firewall documentation</name>
  <files>docker-compose.metabase.yaml</files>
  <action>
Create `docker-compose.metabase.yaml` in the repo root -- this runs on the user's Windows desktop via Docker Desktop, NOT on the DO droplet. Per D-01 and D-05:

```yaml
# Local Metabase -- runs on Windows desktop via Docker Desktop
# Connects to production Postgres on DO droplet
# Usage: docker compose -f docker-compose.metabase.yaml up -d
# Requires: .env.metabase (copy from .env.metabase.template)

services:
  metabase:
    image: metabase/metabase:v0.59.4
    ports:
      - "3001:3000"
    env_file:
      - .env.metabase
    mem_limit: 1536m
    mem_reservation: 512m
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 120s
```

Key design decisions:
- Port 3001:3000 maps Metabase internal port 3000 to localhost:3001 (per INFRA-01, avoids Grafana collision if user has it locally)
- `mem_limit: 1536m` (1.5GB) per INFRA-03 -- Docker Desktop enforces this on Windows
- `mem_reservation: 512m` to ensure some memory is always available
- JAVA_OPTS with -Xmx768m comes from .env.metabase (loaded via env_file)
- healthcheck with 120s start_period because Metabase JVM startup is slow
- No volumes needed -- all state persists in the DO Postgres metabaseappdb
- No depends_on -- Postgres is remote on DO, not a local service

Do NOT modify `docker-compose.prod.yaml` -- per D-01, Metabase does not run on the DO droplet.

Add a comment block at the top of docker-compose.metabase.yaml documenting the Cloud Firewall requirement (per D-02/INFRA-05):

```
# PREREQUISITE: DO Cloud Firewall must allow TCP 5432 from your home IP
# In DO Console: Networking > Firewalls > [your firewall]
# Add inbound rule: TCP 5432, Sources: [your home IP]/32
# This allows Metabase on your desktop to reach Postgres on DO
```
