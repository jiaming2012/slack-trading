## Key finding (drives every recommendation)
`eventmodels` is the **newer, event-sourcing-integrated** copy; `src/go/models` is the **legacy Slack-framework** copy.
The 13 diverged types show a consistent modernization in the eventmodels copy:
- single-price tick model (`tick.Price`) vs legacy bid/ask (`tick.Bid`/`tick.Ask`)
- embeds ESDB envelopes (`BaseRequestEvent` / `BaseResponseEvent`)
- newer identifiers: `ErrDuplicateCloseTrade` (vs `DuplicateCloseTradeErr`), `CalculateUnrealizedPL` (vs `UnrealizedPL`), `CreateSignalRequestEventV1DTO` (vs `NewSignalRequestEvent`)

**Liveness:** The modern backtester uses its OWN `backtester-api/models` package — NONE of these 47 collisions live there. The collisions are entirely the old Slack account/strategy/price-level framework. Of that framework, only the ESDB **AccountWorkerClient** path is wired into `cmd/main.go` (line 392) + `SlackNotifierClient` (389) + `tradeapi` handler + `eventservices/account.go`. **That wired path references the `eventmodels` copies.** The `models` copies are referenced only by unwired/dead packages (`worker/`, `handler/` [imported by nobody], `slack/`, `indicators/`, `eventconsumers/candle.go`, `tradingbot.go`, `rsibot.go`) and `_test.go` files.

Default recommendation therefore: **eventmodels is canonical for all 47.** Confidence varies with divergence + lost methods.

## Item 5 — eventmodels files that import `models` (the cross-package dependency co-location resolves)
There is **no compile cycle today**: `src/go/models` does NOT import `eventmodels` (one-directional). But **6 eventmodels files reach back into `models`**, and every symbol they pull is itself a colliding type — i.e. these files use the *legacy* copy of a type that also exists in their own package. Folding `models` into `eventmodels` (making eventmodels canonical) lets these files drop the `models` import and reference the local copy, eliminating the awkward self-referential cross-package dependency:

| eventmodels file | models symbols imported |
|---|---|
| `trendspider.go` | `models.Direction`, `models.Up`, `models.Down`, `models.Tick`, `models.Trades` |
| `balance.go` | `models.RealizedPL`, `models.Volume`, `models.Vwap` |
| `get_strategies_response_event.go` | `models.Strategy` |
| `bottraderequest.go` | `models.Trade` |
| `addaccountresponsevent.go` | `models.Account` |
| `addstrategyrequest.go` | `models.Direction` |

Note: because these files currently bind to the *legacy* (`models`) copy of diverged types (`Trade`, `Account`, `Strategy`, `Tick`, `Trades`), switching them to the eventmodels copy is a **behavioral change** (bid/ask→price, ESDB envelopes). This is the concrete blast radius of picking eventmodels canonical for those diverged rows.

## Fable canonical decisions (final — 2026-07-05)

**Global ruling:** the `eventmodels` copy is canonical for all 47 colliding types. The merged package is named `models` at `src/go/models/` (per spec: the event-driven *naming* dies; the newer *content* survives). The 249 non-colliding eventmodels types move mechanically; the 18 non-colliding models types stay.

**Legacy-caller strategy (binding on the executor):** dead-but-compiled legacy packages (`worker/`, `handler/`, `slack/`, `indicators/`, `sheets`, `eventconsumers/candle.go`, `tradingbot.go`, `rsibot.go`) are ADAPTED to the canonical shapes (bid/ask → price model, etc.). NEVER build superset types or re-add legacy fields to canonical structs — extra fields change JSON marshaling of live ESDB/API payloads and would break the G4 byte-for-byte gate. Dead-code behavior fidelity is not a goal; compiling is (G1).

**Per-type rulings on flagged rows:**

| type | ruling | method accounting |
|---|---|---|
| Candle | eventmodels canonical | `Update(price)` **ported** (additive; keeps 9 legacy files compiling) |
| CloseTradeRequestV1 | eventmodels canonical | `Validate()` **ported** (cheap capability preservation; adapt internals if they referenced legacy symbols) |
| Datafeed | eventmodels canonical | `Bid()`/`Offer()` **dropped-legacy** — reason: they require the `LastBid`/`LastOffer` fields the canonical copy collapsed into `LastTick`; porting would resurrect a deliberately-removed shape. Referencing test adapted to `LastTick`, or the specific Bid/Offer assertions removed with a dropped-legacy note in the commit. |
| Account, Tick, Trade, Trades, Strategy, ExitCondition (MED) | eventmodels canonical, confirmed | method sets identical — no ports |
| 34 identical-decl + remaining 4 diverged | eventmodels canonical | no ports needed |

**Cross-package edge:** the 6 eventmodels files importing `models` (`trendspider.go`, `balance.go`, `get_strategies_response_event.go`, `bottraderequest.go`, `addaccountresponsevent.go`, `addstrategyrequest.go`) co-locate and bind the canonical copies; compile fixes there follow the legacy-caller strategy.

**Safety expectation:** the live wired path (`AccountWorkerClient`, `SlackNotifierClient`, `tradeapi`, `eventservices/account.go`) already binds the eventmodels copies, so live behavior must be byte-identical post-merge — G4 verifies this. Any G4 diff means the executor changed a canonical type's shape and must stop.
